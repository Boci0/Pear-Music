# Workspace Agent Rules

- **Git Branching Strategy**: Never commit directly to `main`. Create or switch to a feature branch before making any git commits.
- **Ignored Documentation**: All plan and fixing plan markdown files (`*_FIX_PLAN.md`, `*plan*.md`, `*Fix Plan*.md`, `part 2Ghost Pairing.md`, `implementation_plan.md`, `walkthrough.md`) must remain ignored in `.gitignore`.

# Communication & Writing Style Rules

1. **Zero Em Dashes**:
   - Never output em dashes (—) or en dashes (–) in any user responses, markdown documentation, commit messages, or release notes. Replace dash pauses with standard commas, colons, or parentheses.

2. **No AI Clichés, Preambles, or Buzzwords**:
   - Avoid artificial transitions ("Here is...", "In conclusion...", "It is worth noting that...", "Let's dive into...").
   - Avoid buzzwords like "seamless", "game-changer", "testament", "tapestry", "nestled", "unleash", "elevate", "delve".

3. **Natural Technical Prose (Avoid AI Bullet-List Overuse)**:
   - Do not default to structured multi-level bullet point dumps.
   - Write in plain, direct technical sentences and short paragraphs as a human developer would write.
   - Keep answers minimal, exact, and focused on actual code and commands.
